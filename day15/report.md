# День 15. Устаревание и конфликты памяти

Память лежит в `memory.json`, диалог в `dialog.json`. Правила записи задаёт код, не модель.

| Вид | Ключи | Правило |
| --- | --- | --- |
| скаляр, долговременная | срок, статус, версия, требование, подход | новое значение заменяет старое, рядом не добавляется |
| список, долговременная | решения | пункты накапливаются, повтор того же текста не дублируется |
| рабочая память | задача, шаг, заметка | живёт, пока задача не завершена; `/done` её очищает |

У каждого факта есть время записи. Если приходит значение со более ранним временем, код его отбрасывает, актуальное не трогает. Замена пишется в журнал: было → стало. Журнал в промпт не попадает, чтобы старые значения туда не просочились. В промпт идёт только блок «Актуальная память»; из истории диалога код вычищает уже заменённые формулировки.

Факты из реплики извлекает модель (JSON), код проверяет ключи и применяет правила. Если JSON не разобрался, код подхватывает только явные формулировки вроде «срок сдвинулся», «версия релиза теперь», «требование отменили».

## Как проверяли

Один непрерывный диалог, модель deepseek-flash. Сначала задали вводные, потом по очереди сменили четыре факта. После каждой смены спрашивали актуальное значение. В конце команда `/done` и вопрос про задачу, срок и статус.

Стартовые значения: срок 1 декабря 2026, требование «двухфакторная аутентификация при оплате», подход «синхронный REST без очередей», версия 2.1.0, статус «в работе», рабочая задача «подготовить оплату заказов в магазине».

## Результаты

| Шаг | Что записала память | Ответ на вопрос «какое сейчас значение?» | Устаревшее в ответе | Устаревшее в промпте |
| --- | --- | --- | --- | --- |
| срок сдвинулся на 15 декабря 2026 | замена в журнале: 1 декабря 2026 → 15 декабря 2026 | «Срок сдачи — 15 декабря 2026» | нет | нет |
| требование отменили | двухфакторная аутентификация при оплате → отменено | «Требование сейчас — отменено, то есть не действует» | нет | нет |

Смен скаляров за весь диалог: 5. Четыре из них — по ходу разговора (срок, требование, подход, версия), пятая — статус «в работе» → «завершено» на команде `/done`.

Вопросов про актуальное значение: 4. Агент назвал устаревшее значение в ответе на вопрос: 0 из 4. Во всех ходах диалога, включая сообщения о смене факта, устаревшее в ответе: 0. Ходов, где устаревшее попало в промпт: 0. Переделка ответа из-за устаревшего в черновике не понадобилась: 0.

После смены срока модель ещё раз перечислила остальные вводные (2FA, синхронный REST, версия 2.1.0). На тот момент они ещё были актуальны, это не ошибка. После отмены требования и смены подхода в сводке уже стояли новые значения.

### Очистка

До `/done` в рабочей памяти была задача «подготовить оплату заказов в магазине». После команды рабочая память пуста, долговременные факты на месте: срок 15 декабря 2026, требование отменено, подход через очередь сообщений, версия 2.2.0, статус завершено, решение про вебхуки в списке, журнал замен сохранён.

На вопрос «Какая сейчас задача? Какой срок и какой статус?» модель ответила: «Задача — релиз оплаты заказов в интернет-магазине. Срок — 15 декабря 2026. Статус — завершено». Срок и статус верные. Формулировку рабочей задачи она не вернула, но и не сказала, что рабочей памяти нет: взяла название проекта из системного промпта.

## Что нашлось по ходу

Проверка устаревшего ищет точную формулировку, которая была заменена. Сокращения и пересказ код не считает. После отмены требования модель написала «требование про 2FA при оплате отменено», после смены подхода — «не синхронный REST». Полных старых фраз «двухфакторная аутентификация при оплате» и «синхронный REST без очередей» в этих ответах нет, поэтому счётчик остался нулевым. Если модель назовёт старое значение другими словами, проверка это пропустит.

Из истории диалога код вычищает только точные старые строки. Короткий кусок вроде «синхронный REST» может остаться в реплике, если он не совпадает с заменённым текстом целиком.

Извлечение фактов в этом прогоне сработало на всех четырёх сменах и на стартовых вводных. Если факт сформулировать расплывчато, без явной фразы и так, что модель его не извлечёт, память не обновится.

Запуск:

python -m unittest test_memory.py

python check_memory.py

Вручную, по одной команде за запуск:

python agent.py Начинаем задачу: подготовить оплату заказов. Срок — 1 декабря 2026.

python agent.py Срок сдвинулся: дедлайн теперь 15 декабря 2026.

python agent.py Какой сейчас срок сдачи?

python agent.py /memory

python agent.py /log

python agent.py /done
