# День 17. Первый инструмент MCP

В первой версии дня 17 MCP-сервер оборачивал учебный локальный HTTP-трекер заказов. По просьбе сделать «как в задании», не учебный API, сервер переведён на настоящий GitHub REST API (`https://api.github.com`). Репозиторий по умолчанию — публичный `mmoshkina3-ui/ai-advent-challenge-10`. Чтение работает без токена; необязательный `GITHUB_TOKEN` только поднимает лимит запросов. Токен в репозиторий не попадает: он читается из окружения или из `day17/.env`, который в `.gitignore`.

Клиент и диспетчер те же, что в дне 16: соединение по stdio, `list_tools`, перевод схем в формат запроса к модели, вызов `Client.call_tool`. Сервер свой, запускается тем же интерпретатором: `sys.executable day17/server.py`. Node.js не нужен. Владелец и имя репозитория задаются переменными `GITHUB_OWNER` и `GITHUB_REPO` и могут быть переопределены аргументами инструментов.

Для офлайн-тестов остаётся локальный мок с теми же маршрутами GitHub (`github_mock.py`). В обычном запуске он не стартует.

## Регистрация, схема и результат

Три инструмента регистрируются декоратором `@server.tool` с именем и описанием. Параметры — аннотации типов и `pydantic.Field(description=...)`. Из них SDK собирает JSON Schema, которую клиент получает в `tools/list`.

| Инструмент | Параметры | Что возвращает |
| --- | --- | --- |
| `repo_info` | необязательные `owner`, `repo` | имя, описание, ветка по умолчанию, число открытых issues, ссылка |
| `list_commits` | `limit` (1–30, по умолчанию 5), необязательные `path`, `ref`, `owner`, `repo` | короткие sha, сообщение, автор, дата |
| `get_file` | обязательный `path` (например `day16/report.md`), необязательные `ref`, `owner`, `repo` | текст файла или список папки; длинный файл обрезается |

Инструмент делает GET в GitHub и отдаёт разобранный JSON. Ошибки не роняют протокол: 404 возвращает `error: not_found`, исчерпанный лимит — `error: rate_limited` со подсказкой про `GITHUB_TOKEN`, неверный токен — `unauthorized`.

## Как запустить

Нужны Python 3, пакет `mcp` и интернет:

```powershell
pip install -U "mcp>=2"
# или: pip install -r day17/requirements.txt
```

Ключ модели — в окружении `DEEPSEEK_API_KEY` или в `day02/.env` / `day17/.env`. Токен GitHub не обязателен. Проверка без модели (мок, сеть не нужна):

```powershell
cd day17
python -m unittest test_github.py
```

Прямой вызов и прогон с моделью (настоящий GitHub):

```powershell
python check_github.py
python agent.py Что делали в последних трёх коммитах?
```

На странице http://127.0.0.1:8765/ день 17 поднимает тот же сервер. Если пакета `mcp` нет, страница не падает, а показывает, чего не хватает. Сервер стартует тем же `python`, которым запущена страница.

## Результаты

Юнит-тесты: 19 из 19. Восемнадцать идут через локальный мок и проверяют схемы, 404, лимит, чтение файла и диспетчер агента. Один живой тест ходит в `api.github.com` и пропускается, если сети нет (или если лимит GitHub уже исчерпан).

Прогон с настоящей моделью `deepseek-flash` и настоящим GitHub. MCP-соединение установилось, сервер назвался `github-repo` и вернул три инструмента. В схеме `get_file` параметр `path` обязательный, в описании есть пример `day16/report.md`. Прямой вызов `list_commits({"limit": 3})` вернул `192eb47`, `59b435d` и `5f0aeb9`. Прямой вызов `get_file({"path": "day16/report.md"})` вернул файл целиком (8501 байт, без обрезки), в тексте есть `read_text_file`, `list_directory` и `calculate`.

| Шаг | Источник | Вызов | Результат |
| --- | --- | --- | --- |
| 1 | MCP | `list_commits({"limit": 3})` | 192eb47, 59b435d, 5f0aeb9 и их сообщения |
| 2 | — | ответ текстом | все три sha и точные сообщения из API |

Модель сама выбрала `list_commits` с `limit: 3`. В ответе есть все три коротких sha и формулировки коммитов слово в слово, плюс краткий пересказ. Это совпадает с прямым вызовом API: день 17 — свой MCP-сервер вокруг локального API заказов, день 16 — инструменты публичного MCP-сервера, день 15 — обновление памяти и разрешение конфликтов. Даты в ответе модели указаны как 24, 23 и 22 ноября 2026 (по полю `date` коммита, это UTC; в Москве это тот же календарный день).

## Ограничения

Без `GITHUB_TOKEN` у неавторизованных запросов к GitHub лимит 60 в час на IP. Если он исчерпан, инструмент возвращает понятную ошибку, а не падает. Для страницы и демо на одном компьютере этого обычно хватает; если запросы станут частыми, лучше задать токен в окружении.

`get_file` обрезает текст после 8000 символов и не показывает двоичные файлы. Каталог возвращается списком имён, а не содержимым всех файлов сразу.

Модель могла бы ответить «из головы» и не вызвать инструмент. В этом прогоне она вызвала его оба раза; защита от выдумки — промпт и проверка факта вызова, а не запрет в коде отвечать без инструмента.

Офлайн-тесты идут в мок, а не в GitHub. Мок повторяет маршруты и коды ошибок, но это не полная копия API. Живой тест один и зависит от сети и лимита.
